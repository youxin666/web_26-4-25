# 未通过投稿转为草稿设计

## 目标

允许投稿作者将自己的“未通过”文章恢复为草稿，随后继续编辑并再次提交审核。待审核与已发布文章不提供该操作。

## 页面交互

- “转为草稿”按钮仅出现在“未通过”列表的文章卡片中，位于“查看投稿”右侧。
- 按钮沿用“查看投稿”的颜色、字号、间距、悬停和键盘焦点样式。
- 点击后暂时禁用按钮，避免重复请求。
- 转换成功后，将文章从“未通过”分组移动到“草稿”分组，自动切换到“草稿”标签，并保留当前标签记忆。
- 草稿卡片显示“继续编辑”，打开后恢复完整编辑能力。
- 转换失败时恢复按钮并显示明确错误提示，不改变前端分组。

## 接口与状态保护

- 新增用户侧状态转换接口，只接受当前登录用户自己的文章。
- 数据库更新带所有者和状态条件，仅允许 `rejected -> draft`。
- 转换时清除审核拒绝状态及审核时间，增加文章版本并更新时间，正文、摘要、分类、封面和附件保持不变。
- 对草稿、待审核、已发布或不属于当前用户的文章拒绝转换，避免绕过审核流程。
- 返回更新后的文章 DTO，供前端原位更新分组。

## 错误处理

- 未登录返回认证错误。
- 找不到文章或无权限时不泄露文章归属信息。
- 状态不允许转换时返回稳定错误码。
- 数据库失败返回通用失败响应，前端显示本地化失败提示。

## 验证

- 单元/契约测试覆盖仅未通过文章显示按钮、按钮样式复用、成功后切换草稿、请求防重复及失败恢复。
- Worker 测试覆盖本人未通过文章成功转换，以及其他状态和其他用户无法转换。
- 部署后验证线上脚本、接口路由和缓存版本；不使用真实用户文章做破坏性测试。
