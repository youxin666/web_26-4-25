# 普通用户文章投稿与审核发布设计

## 目标

为 `blog.858846.xyz` 增加普通用户文章投稿功能。用户必须注册并登录后才能创建文章、上传图片、保存草稿和提交审核。投稿不会直接公开；管理员在现有独立后台查看完整投稿后，点击“发布”才会把文章加入公开博客。

本功能保持现有公开文章读取架构：公开文章继续存储在 Cloudflare KV，并自动进入首页、文章列表、文章页、RSS 和 sitemap。用户草稿与审核状态不进入公开 KV。

## 已确认范围

### 普通用户

- 必须登录后才能访问发布页和“我的文章”。
- 可以创建草稿、继续编辑草稿、上传图片、选择封面、实时预览并提交审核。
- 可以查看自己的草稿、待审核文章和已发布文章。
- 草稿可编辑；提交为待审核后锁定编辑；已发布文章只读。
- 不能读取或修改其他用户的投稿。

### 管理员

- 在现有 `/admin/` 后台增加“用户投稿”区域。
- 可以查看投稿作者、标题、分类、摘要、正文预览、附件和提交时间。
- 只有“发布”操作。没有退回、拒绝、退回原因或额外审核状态。
- 未发布投稿持续保留在待审核列表。

### 不在本期范围

- 用户直接公开发布。
- 管理员退回或拒绝投稿。
- 投稿评论、协作编辑、版本历史和定时发布。
- 已发布文章由投稿用户直接修改。
- 将现有正式文章从 KV 迁移到 D1。

## 技术架构

采用“D1 投稿 + R2 图片 + KV 正式文章”的分层方案。

### D1

D1 保存普通用户投稿和图片元数据，支持按用户、状态和时间查询。

建议新增两张表：

1. `blog_user_articles`
   - `id`
   - `user_id`
   - `title`
   - `permalink`
   - `category`
   - `excerpt`
   - `content_markdown`
   - `cover_asset_id`
   - `status`：`draft`、`pending`、`published`
   - `published_permalink`
   - `created_at`
   - `updated_at`
   - `submitted_at`
   - `published_at`

2. `blog_user_article_assets`
   - `id`
   - `article_id`
   - `user_id`
   - `object_key`
   - `mime_type`
   - `size_bytes`
   - `width`
   - `height`
   - `alt_text`
   - `caption`
   - `created_at`

数据库必须为 `user_id + status`、`article_id` 和 `submitted_at` 建立索引。`cover_asset_id` 必须属于当前文章的附件集合。

### R2

新增 R2 binding，例如 `BLOG_MEDIA`，保存投稿图片。对象路径采用随机 ID，不使用用户原始文件名，例如：

`user-articles/<user-id>/<article-id>/<asset-id>.<ext>`

公开文章继续引用同一 R2 图片，不在发布时复制对象。图片始终通过 Worker 的受控媒体路由读取：`draft` 和 `pending` 图片只允许所属用户与管理员查看，关联投稿进入 `published` 后才允许匿名公开访问和长期缓存。响应设置正确的 `Content-Type`、缓存和安全头。

### KV

管理员确认发布后，Worker 把投稿转换成现有正式文章对象并写入：

- `article:<permalink>`
- `articles:index`

正式文章额外保留 `authorName` 和来源投稿 ID。文章页显示“作者：<昵称>”，不公开邮箱、用户 ID 或 R2 内部对象键。首页文章卡片不显示作者，保持当前布局。

## 状态流转

1. 新建文章：`draft`
2. 用户提交审核：`draft -> pending`
3. 管理员发布：`pending -> published`

`pending` 和 `published` 状态禁止普通用户修改。管理员发布操作必须幂等：同一投稿重复请求不能生成重复公开文章。KV 写入成功后才将 D1 状态更新为 `published`；若状态更新失败，重试应覆盖同一 permalink，而不是创建新文章。

## 页面与导航

### 登录用户菜单

点击用户名展开：

- 发布文章
- 我的文章
- 退出登录

未登录时不显示投稿入口。直接访问 `/publish` 或 `/my-articles` 时跳转 `/login`，并携带安全的站内返回地址。

### 发布页 `/publish`

采用已选择的 A 方案：桌面双栏实时预览。

- 左栏：元数据、Markdown 工具栏、正文、图片附件和保存状态。
- 右栏：使用与正式文章相同的 Markdown 渲染结果实时预览。
- 手机端：显示“编辑 / 预览”标签，不并排压缩两栏。

字段与限制：

- 标题：必填，最多 120 字。
- 分类：可选择现有分类，也可输入新分类。
- 摘要：自动从正文生成，可手动修改，最多 240 字。
- 正文：Markdown，最多 30,000 字。
- 封面：从本文章已上传图片中选择；封面计入三张图片上限。

编辑工具栏支持：

- 二级标题、三级标题
- 粗体、斜体、引用
- 无序列表、有序列表
- 代码块、链接、分隔线
- 插入图片

图片上传后可以填写无障碍描述和图注、选择封面、插入当前光标位置或删除。

### 我的文章 `/my-articles`

按草稿、待审核和已发布分组显示。每项显示标题、分类、更新时间、状态和封面缩略图。

- 草稿：继续编辑。
- 待审核：只读预览。
- 已发布：打开公开文章。

### 管理后台 `/admin/`

保留管理员文章创建功能，并新增用户投稿列表和完整预览。管理员点击“发布”后显示明确结果和公开文章地址。

## 图片规则

- 每篇普通用户文章最多 3 张图片，封面计入数量。
- 单张不超过 5 MB。
- 只支持 JPG、PNG、WebP 和 GIF。
- 服务端同时检查扩展名、声明 MIME、实际文件签名和文件大小。
- 拒绝 SVG、HTML、脚本、伪装图片和未知格式。
- 上传接口必须先验证登录、文章所有权和文章状态。
- 删除图片时同步删除 R2 对象和 D1 元数据；已插入正文的图片删除前应提示并清除对应 Markdown 引用。

## 自动保存

- 输入停止约 3 秒后自动保存草稿到 D1。
- 同时保存浏览器本地备份。
- 页面显示“正在保存”“已保存”“保存失败，已保留本地备份”等状态。
- 网络恢复后可以再次保存，不自动覆盖较新的服务器版本。
- 使用 `updated_at` 进行乐观并发检查，避免多个标签页静默覆盖。
- 提交审核前强制执行一次服务器保存和完整校验。

## API 设计

普通用户接口：

- `POST /api/user/articles`：创建草稿。
- `GET /api/user/articles`：获取当前用户文章列表。
- `GET /api/user/articles/:id`：获取当前用户单篇投稿。
- `PUT /api/user/articles/:id`：更新当前用户草稿。
- `POST /api/user/articles/:id/submit`：提交审核。
- `POST /api/user/articles/:id/assets`：上传图片。
- `PUT /api/user/articles/:id/assets/:assetId`：更新 alt 和图注。
- `DELETE /api/user/articles/:id/assets/:assetId`：删除草稿图片。
- `GET /media/user-articles/:assetId`：受控读取图片。

管理员接口：

- `GET /api/admin/submissions`：获取待审核投稿。
- `GET /api/admin/submissions/:id`：获取完整投稿。
- `POST /api/admin/submissions/:id/publish`：发布投稿。

所有写接口只接受同源请求和预期内容类型。用户接口验证普通用户会话，管理员接口验证管理员会话。

## Markdown 与文章元素

正文只保存 Markdown，不接受用户直接提交 HTML。预览和正式文章复用同一服务端安全渲染规则，支持现有样例文章所需元素：

- 章节标题和段落
- 粗体、斜体、链接
- 有序和无序列表
- 引用与分隔线
- 代码块
- 正文图片、alt 和图注

图片 Markdown URL 必须指向当前投稿已登记的站内媒体路由，不能借助正文引用未授权的内部对象。

## 安全与隐私

- 复用现有 HttpOnly、Secure、SameSite 用户会话 Cookie。
- 每个用户接口都验证资源所有权，避免横向越权。
- 普通用户提交的 permalink 只作为建议值，发布时由服务端标准化并解决冲突。
- 公开页面只显示作者昵称，不显示邮箱、用户 ID、内部资源键或会话信息。
- 对创建草稿、自动保存、上传和提交设置合理的用户级速率限制。
- 所有用户输入在 HTML、属性、URL 和 Markdown 上下文中分别转义或校验。
- 媒体响应添加 `X-Content-Type-Options: nosniff` 和合适的 CSP/缓存策略。

## 错误处理

- 图片上传失败不影响已保存正文。
- 自动保存失败时保留本地备份并允许手动重试。
- 提交审核失败时文章保持 `draft`，不进入半锁定状态。
- 发布失败时投稿保持 `pending`，管理员可安全重试。
- 文章字段、图片数量、图片归属和封面归属必须在客户端提示并由服务端再次验证。
- API 返回稳定错误码与可本地化的中文/英文提示，不把数据库或存储错误细节返回前端。

## 测试与验收

### 自动测试

- 未登录访问发布页和投稿 API 被拒绝或跳转登录。
- 用户只能读取和修改自己的草稿。
- 待审核和已发布文章拒绝普通用户更新。
- 标题、摘要、正文长度限制生效。
- 第四张图片、超过 5 MB 的图片、错误 MIME 和伪装文件被拒绝。
- 封面必须属于当前文章附件。
- 自动保存和乐观并发冲突按设计处理。
- 提交审核锁定文章。
- 管理员发布操作幂等，并更新 KV 索引和 D1 状态。
- 用户投稿发布后出现在首页、文章页、RSS 和 sitemap。

### 浏览器验收

- 桌面双栏编辑与实时预览同步。
- 390px 手机端编辑/预览标签切换，无横向溢出和遮挡。
- 深色模式和中英文文案完整。
- 图片上传、选择封面、插入正文、删除和图注显示正常。
- 用户菜单、我的文章状态列表和管理员待审核列表可完整操作。
- 键盘焦点、按钮标签、图片 alt 和减少动态效果符合可访问性要求。

## 部署要求

- 新增并绑定 R2 bucket `BLOG_MEDIA`。
- 执行 D1 migration 创建投稿与附件表。
- 不把 API Token、R2 密钥或会话 Secret 写入源码或前端。
- 先在本地和 Wrangler dry-run 验证，再部署 Worker。
- 部署后使用真实用户会话验证投稿全流程，并确认公开文章、RSS 和 sitemap。
