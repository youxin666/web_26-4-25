# 用户账户与公开资料页设计

## 目标

为已登录读者提供“我的账户”页面，允许查看和编辑头像、昵称与个人简介；在文章评论区点击评论者头像时，可以进入该用户的公开资料页。账户页沿用 Rowan Notes 当前的玻璃卡片和蓝紫色视觉体系，并适配中英文、浅色和深色模式。

## 页面与导航

登录后的顶部账户菜单新增“我的账户”，链接到 `/account`。页面默认显示资料卡，包含头像、昵称、邮箱、简介、已发布文章数和加入年份。邮箱仅展示，不可修改。没有头像时显示昵称首字母，没有简介时显示明确的未填写提示。

资料卡右上角显示铅笔按钮。点击后进入原位编辑状态：头像区域显示上传入口，昵称和简介切换为输入控件，底部显示“取消”和“保存资料”。取消恢复保存前内容；保存成功后立即更新资料卡以及当前页面中使用该用户昵称或头像的位置。

评论区的用户头像和昵称链接到 `/user/:id`。公开页使用相同的资料卡层级，但只显示头像、昵称、简介和已发布文章数，不显示邮箱、加入年份、编辑按钮或文章列表。

## 数据模型与存储

在现有 `blog_users` 表增加可空字段：

- `avatar_key TEXT`：头像在 R2 中的对象键。
- `bio TEXT`：个人简介。
- `updated_at TEXT`：资料最后更新时间。

昵称继续使用现有 `display_name`。头像文件写入现有 `BLOG_MEDIA` R2 存储，使用独立的用户头像路径，数据库只保存对象键。替换头像成功后清理旧头像对象，删除失败不影响新资料保存。

已发布文章数直接从现有 `blog_user_articles` 表按 `user_id` 和 `status = 'published'` 统计，不保存冗余计数字段。

## API 与权限

- `GET /api/user/profile`：要求登录，返回本人资料、邮箱、加入年份和已发布文章数。
- `PUT /api/user/profile`：要求登录，仅接受昵称和简介；服务端校验长度并更新时间。
- `POST /api/user/avatar`：要求登录，接收单个 JPG、PNG 或 WebP 文件，校验 MIME 类型和文件大小，写入 R2 后更新用户记录。
- `GET /api/users/:id/profile`：公开接口，只返回用户 ID、头像地址、昵称、简介和已发布文章数。
- `GET /media/user-avatar/:id`：根据当前头像对象键读取 R2 内容，设置正确内容类型和缓存头。

所有本人接口从现有会话解析用户 ID，不接受客户端传入的用户 ID。公开接口采用字段白名单，确保邮箱、密码哈希、会话信息和更新时间不会泄露。

## 校验与错误处理

昵称去除首尾空格后必须为 1 至 40 个字符；简介最多 300 个字符。头像最大 5 MB，只接受 JPG、PNG 和 WebP。服务端以实际 MIME 类型和文件头为准，文件扩展名不作为唯一判断依据。

表单保存期间禁用重复提交。失败时在表单内显示中英文错误信息并保留输入内容；成功时退出编辑状态并显示保存成功提示。公开用户不存在时返回 404 页面。头像加载失败时回退到昵称首字母。

## 响应式与视觉状态

桌面端资料卡采用头像列与资料列布局；手机端改为纵向排列。铅笔按钮固定在资料卡右上角，点击区域不小于 40 像素。编辑状态不改变资料卡整体位置，避免页面跳动。浅色和深色模式均使用现有颜色变量。

## 验证

自动化检查覆盖：数据库迁移、未登录拦截、本人字段返回、公开字段隔离、昵称和简介校验、头像格式与大小限制、旧头像替换、发布文章数统计、中英文文案和导航入口。

真实浏览器验证覆盖桌面与手机宽度、浅色与深色模式、无头像/无简介状态、编辑取消、保存成功、上传失败保留表单，以及从评论头像进入公开主页。生产部署后再次验证登录账户页和公开主页，不在日志或截图中暴露邮箱之外的敏感信息。
